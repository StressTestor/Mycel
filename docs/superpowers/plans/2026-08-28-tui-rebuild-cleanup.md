## Correctness / honesty

1. **Seed frames carry epoch 0.** `production.rs:3626-3635` — the two construction-time `transcript.push(TranscriptEvent::Status(...), 0)` calls render as `17:00:00` (epoch 0, local) in the new timestamp gutter. Pass the real wall clock (same expression as `InteractiveLoopState::now_ms`: `SystemTime::now` → epoch ms; a small free fn both can call). Test: seed a reducer the same way and assert `at_ms != 0`.
2. **Light theme split-brain → honest unification.** `tui_config.rs::active_theme` maps `Light` to amanita while claiming (falsely — zero `.bg()` calls in components) the card paints its own panel. `resolved_theme` is already deleted (PR3), so unification is done; make it honest: when the configured theme is `light`, surface a startup warning through the existing `prepared.warning` channel ("light theme is not supported by the rebuilt TUI yet; using amanita") and fix the `active_theme` comment. Also amend `docs/design/tui-implementation-spec.md` §4's "`light` keeps the current light palette" sentence to match reality (light = warned alias of amanita until a light theme is designed). Test: config with `theme = "light"` produces the warning; `theme = "amanita"` does not.
3. **Theme name table single-source + fail-loud.** `Theme::ALL` (theme.rs:113) and `Theme::by_name` (theme.rs:124) are two hand-synced lists; `active_theme`'s `unwrap_or_else(amanita)` silently swallows any future drift. Single-source (e.g. `ALL` as `[(name, constructor)]` driving both, or `by_name` iterating `ALL`), and make resolution of a parse-validated name that fails a `debug_assert!` before the amanita fallback. Test: for every name in `Theme::ALL`, `ThemeName::parse(name)` → `active_theme` returns a theme with that exact `.name` (the missing end-to-end round trip).
4. **Gate dot: never claim unverified state.** `build_header` (production.rs) hardcodes `gate_ok: true`; the card renders a green `● ok` on a security status nobody checked. Until PR4 wires the live read: change `SubstrateSummary.gate_ok: bool` to `gate: GateDisplay { Ok, Blocked, Unknown }` (or minimal: add `gate_known: bool`), render Unknown as a `muted` dot with no "ok"/"blocked" word, and construct Unknown in `build_header`. Keep the existing ok/blocked rendering for PR4 to activate. Update header tests.
5. **Startup recent-sessions read: no repair scan, no second lock stall.** `build_header` → `session_index.list(None)` re-acquires the cross-process index lock (up to 2s stall) and re-runs the full repair scan (reads every session's whole `records.jsonl`) that `prepare_interactive`'s register/refresh just did (production.rs:3081-3083). Fix with the cheapest correct option, in order of preference: (a) reuse/return the summaries the earlier refresh already produced, (b) add a read-only `SessionIndex` method that parses the persisted `index.jsonl` top-N without repair or blocking lock acquisition, (c) move the read to a background thread that fills `header.recent` after first paint. Document the choice. Test at the seam you introduce.

## Rendering bugs

6. **Header narrow-width degradation is documented but not implemented.** `header.rs:50-76` — below ~59 cells, rows get raggedly truncated: identity text cut mid-string and the right border dropped, while top/bottom rules still render full width (open-sided box). Implement the documented staged collapse: drop the right column (and its divider) first, then shrink/drop identity, keep logo + BOTH border glyphs for as long as ≥ ~20 cells. Extend `header_card_survives_narrow_widths` to assert every interior row still ENDS with the `╎` border glyph (after ANSI strip) at widths where the box renders at all.
7. **IDENT_W sized to the sample string.** `header.rs:40` — qualified aliases (`provider:model` collision names from provider_commands.rs:862-887, ~35 chars) overflow `IDENT_W=34`, silently cutting the model name and dropping the context annotation. Size the identity column from its content: `max(visible widths of the 3 identity lines)` clamped to a sane range (e.g. 24..=48), reserve accordingly. Test with a 35+-char model alias asserting the full alias renders at comfortable widths.
8. **Deny-box head can push out its right border.** `components/transcript.rs::deny_lines` — the lead row (`■ DENY <head>`) is not clipped to `inner_w` before the closing ` ╎` is appended, so a long deny head at narrow width truncates the border off. Clip the head spans to `inner_w` (same treatment the subtext gets via wrap) before boxing. Extend the deny test with a long head + narrow width asserting the stripped line ends with `╎`.

## Duplication / drift

Factor a single core (e.g. `pub(crate) fn clip_and_pad(spans: &[Span], target: usize) -> Vec<Span>` in `terminal/compose.rs` or `style.rs`); `push_column` and `fit_spans` both call it (or `fit_spans` IS it, and push_column delegates). Note for the record: `compose::{Region,join_row,assemble}` stay — PR4's rails consume them or they get deleted then.

One shared char-based `short_id(&str) -> String` (put it somewhere neutral, e.g. a small util in mycel-cli), all three call sites converted. Test: non-ASCII id does not panic and yields 8 chars.

## Performance (verified hot-path waste)

13. **Stop rebuilding theme/env/header every 25ms tick.** interactive_view currently calls `active_theme` + `truecolor_enabled()` (env read) per render at ~40Hz, and re-renders the header card each time. Cache on `InteractiveLoopState`: `theme: Theme` and `truecolor: bool` resolved at construction; re-resolve on the `/theme` command path (production.rs ~4515-4539) and keep using the cached value elsewhere; cache the header's rendered `Vec<String>` keyed by `width`, invalidated on resize (`TerminalEvent::Resize` handling ~6691) and theme change. Transcript frames stay per-render (they change). Test at the seams where practical; at minimum assert `/theme` updates the cached theme.
