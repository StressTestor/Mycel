# roadmap

Mycel is now a Rust-only terminal agent. The immediate work is to harden that
one implementation rather than maintain a compatibility body beside it.

## shipped

- Fail-pattern immunity with explicit allow, warn, and refuse outcomes.
- A fail-closed tool gate and protected-path floor.
- Failure observation, inert antibody candidates, and explicit promotion.
- SQLite-backed decay, projections, self-specs, task identity, sclerotia, wake
  conditions, and spore records.
- A terminal agent harness with providers, tools, sessions, MCP, skills, hooks,
  permissions, background work, subagents, swarm mode, goals, Workflow, and
  `/hyphae`.
- Mycel substrate commands in the TUI.
- Native macOS/Linux terminal driving, prompt mode, session management,
  approvals, questions, image paste, local plugins, and provider management.
- Removal of the TypeScript oracle and its browser/editor/server inheritance.

## now: hardening

- Keep provider, protocol, permission, restart, and terminal fixtures adversarial.
- Eliminate descriptor-relative filesystem race windows in local tools.
- Finish structured shell-path protection for gate-sensitive targets.
- Build reproducible signed release artifacts without adding an updater or
  network control plane.

## next: ecology depth

- Improve candidate explanations and evidence without automatic promotion.
- Connect kin-sharing only after its authorization and conflict semantics have
  executable tests.
- Keep interop export inert and explicit.

## later

- Connect kin-sharing and substrate-conditioned spawning only after the
  underlying records have reliable end-to-end product surfaces.
- Harden inert interop export where it serves a demonstrated local workflow.
- Consider non-Unix terminal support only with a real raw-mode, signal, resize,
  and PTY test path. Do not advertise a simulated adapter.

The longer product thesis and non-goals live in `docs/VISION.md`. Current
architecture lives in `ARCHITECTURE.md`; neither substitutes for executable
parity tests.
